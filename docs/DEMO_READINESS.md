Project Jebediah — Pilot Readiness & Demo Runbook

Purpose
-------
This document collects operational guidance needed to run a deterministic, board-ready demonstration of Project Jebediah. It describes the architecture, startup and health verification steps, demo recovery processes, known limitations, and quick troubleshooting notes.

Architecture
------------
Interaction Gateway → Jebediah Memory Service → Embedding Provider (Ollama) → Qdrant → Generation Model

Services
- jebediah-interaction — Interaction Gateway (FastAPI)
- jebediah-memory — Memory Service (FastAPI) that embeds text via Ollama, retrieves from Qdrant, and returns context
- qdrant — Vector store for memories
- ollama — Embedding and local model runtime (external to compose in many deployments)

Service communication
- Services run on Docker network: jebediah_internal
- Interaction → Memory: http://jebediah-memory:8000
- Memory → Ollama: OLLAMA_URL (environment variable) — must be reachable from containers
- Memory → Qdrant: QDRANT_URL (environment variable) — http://qdrant:6333 on same network

Startup procedure
-----------------
Prereqs on the VM:
- Docker Engine and Docker Compose
- Ollama installed and reachable by containers (see "Ollama availability")

1. Verify Docker and network exist:
   - docker network ls | grep jebediah_internal
2. Start services (project root):
   - docker compose -f services/jebediah-memory/docker-compose.yml up -d --build
   - docker compose -f services/jebediah-interaction/docker-compose.yml up -d --build
   - Ensure qdrant is running (docker compose -f services/jebediah-memory/docker-compose.yml up -d qdrant or as per platform)

Ollama availability
-------------------
- The memory service depends on Ollama for embeddings. Containers MUST be able to reach the configured OLLAMA_URL.
- Recommended options to make Ollama reachable:
  1. Run Ollama as a container on the same docker network (recommended for demos)
     - Add/Run an Ollama container attached to the jebediah_internal network and set OLLAMA_URL to http://ollama:11434
  2. Run Ollama on the host and bind to 0.0.0.0:11434 (host-level binding) and ensure firewall rules allow container-to-host connectivity. Then set OLLAMA_URL to the host IP (example: http://100.110.120.15:11434)

Health verification procedure
-----------------------------
Use the demo validation script scripts/demo_check.sh (executable) which performs the following checks from the host:
- Required containers running (jebediah-memory, jebediah-interaction, qdrant)
- Docker network jebediah_internal exists
- memory /health via docker network
- interaction /health via docker network
- qdrant HTTP reachable at qdrant:6333
- Ollama reachable at configured OLLAMA_URL

Demo recovery procedure
-----------------------
Common failures and recovery actions:
- Ollama unreachable → start Ollama on same docker network or rebind host/listen address and retry demo
- Embedding model not installed in Ollama → install nomic-embed-text:v1.5 on the Ollama instance (the adapter validates model digest)
- qdrant unreachable → restart qdrant container: docker restart qdrant
- One service failing on startup → docker compose -f <compose> logs <service> and inspect; rebuild and redeploy if needed

Known limitations
-----------------
- Containers may not see host-bound services unless Ollama is bound to an address reachable by the docker network.
- memory service will return HTTP 503 when the embedding provider is unavailable (intentional behavior for reliability).
- The approved embedding model must be installed into Ollama; otherwise memory will refuse to proceed (returns 503).

Troubleshooting checklist
-------------------------
1. Check containers: docker ps
2. Check network: docker network inspect jebediah_internal
3. Check Ollama from a container: docker run --rm --network jebediah_internal curlimages/curl:8.4.0 -I <OLLAMA_URL>
4. Inspect memory logs: docker logs jebediah-memory --tail 200
5. Inspect interaction logs: docker logs jebediah-interaction --tail 200

Demo run (happy path)
---------------------
1. Ensure Ollama is reachable and the approved embedding model is installed.
2. Ensure qdrant is running and exposes collection jebediah_memory.
3. Start memory and interaction containers via docker compose (build if code changed).
4. Run the demo validation script: scripts/demo_check.sh
5. If the script reports OK, run the end-to-end request:
   docker run --rm --network jebediah_internal curlimages/curl:8.4.0 -sS -X POST -H 'Content-Type: application/json' --data '{"message":"Hello Jebediah. Introduce yourself briefly."}' http://jebediah-interaction:8001/chat

Contact / escalation
--------------------
- If Ollama needs configuration changes, contact the infra owner. For quick help, follow the troubleshooting checklist above.
