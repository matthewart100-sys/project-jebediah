# ADR NNNN: Decision Title

**Status:** Proposed

**Decision level:** Foundational | System | Implementation

**Date:** YYYY-MM-DD

**Decision owner:** Name the accountable project role

**Reviewers:** Name required review roles

## Decision summary

State the selected course in one or two direct sentences. Remove all template
instructions before review.

## Context

Describe the problem, why it requires a durable decision, who or what is
affected, and what happens if no decision is made.

### Verified facts

- List facts supported by repository, test, measurement, or inspected system
  evidence.

### Reported facts

- List trusted but unverified claims and their verification path.

### Working assumptions

- List temporary premises, their impact, and their confirmation conditions.

### Open questions

- List unresolved matters, owners, and resolution gates. Explain why the
  decision can proceed safely despite any remaining question.

## Scope

- State what this decision governs.

## Non-goals

- State adjacent matters this decision deliberately does not resolve.

## Decision drivers

- List the project requirements and constraints used to compare alternatives.

## Considered alternatives

### Alternative A: Descriptive name

Describe the option, how it satisfies the drivers, and its material risks.

### Alternative B: Descriptive name

Describe the option, how it satisfies the drivers, and its material risks.

### Retain the current design

Describe the consequence of making no change. Remove this subsection only when
there is genuinely no current design to retain.

## Decision

Define the chosen responsibility, boundary, or behavior. Be precise enough to
guide dependent work. Do not include unrelated implementation detail.

## Consequences

### Positive

- State benefits and which decision drivers they satisfy.

### Negative

- State costs, risks, constraints, and lost options.

### Neutral

- State notable effects that are neither benefits nor costs.

## Data and provenance impact

Describe authoritative, cached, derived, and temporary information affected;
ownership; provenance; retention; and migration. Write `No impact` with a
reason when this decision cannot affect information.

## Security and privacy impact

Describe trust boundaries, privileges, sensitive information, threats, and
residual risk. Reference private evidence safely when necessary.

## Operations and recovery impact

Describe deployment, health, observability, capacity, backup, restore,
rollback, degraded behavior, and operator ownership.

## Compatibility and migration

Describe consumers, versioning, transition order, rollback, and removal of the
old path. State why migration is unnecessary when no current consumer exists.

## Validation

Define evidence that will show the decision works and criteria that would
trigger reconsideration.

## Follow-up work

- List owned work that is necessary but outside this decision.

## Related documents

- Link current architecture, standards, specifications, issues, and pull
  requests affected by this decision.

## Supersession

**Superseded by:** None

Update both ADRs when a later accepted decision supersedes this one.

## Review record

Record the formal decision and link the pull request containing the actual
reviewed artifacts. Conversation alone is not the review record.
