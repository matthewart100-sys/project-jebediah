# Project Jebediah v0.1.0 Release Notes

## Engineering-foundation release

`v0.1.0` is an engineering-foundation release. It does **not** contain a
Project Jebediah application, deployable service, infrastructure definition,
runtime workflow, data schema, Digital Twin, or supported software capability.

The release makes GitHub the durable, reviewable engineering memory from which
future Project Jebediah work can begin safely.

## Included foundation

- Mission, manifesto, current status, roadmap, and documentation hierarchy
- Repository, engineering, documentation, Git, sprint, contribution, and
  completion standards
- AI onboarding, collaboration roles, durable-memory rules, and Codex
  operating guidance
- Architecture principles, current conceptual architecture, shared
  terminology, component maturity, and tiered ADR governance
- Data ownership and the bounded Digital Twin position
- Testing, security, operations, recovery, and release philosophies
- Pull-request and issue intake templates
- Dependency-free repository validation and a pinned, least-privilege GitHub
  Actions quality gate
- Verified private vulnerability reporting and proportionate `main`
  protection
- Project Genesis audit, clean-room onboarding evidence, and release
  readiness record

## Release identity

- **Release type:** Foundation and documentation
- **Release owner and withdrawal authority:** Repository maintainer
  `matthewart100-sys`
- **Included history:** Initial repository baseline through the immutable
  `v0.1.0` tag target
- **Published artifacts:** Reviewed Git commit, annotated Git tag, and GitHub
  release record
- **Binary, container, model, schema, migration, and deployment artifacts:**
  None

## Verification

Publication requires:

- Complete Project Genesis requirements mapping
- Cross-document and repository-structure audit
- Independent clean-room onboarding evidence
- Local and GitHub documentation-quality success on the final commit
- Verified security reporting and `main` protection state
- Explicit Chief Architect and maintainer release decisions

Exact final evidence is recorded in the
[v0.1.0 Release Checklist](CHECKLIST.md) and the
[Genesis Foundation Audit](../../genesis/GENESIS_FOUNDATION_AUDIT.md).

## Known limitations

- No Project Jebediah application or infrastructure has been implemented.
- No home-lab component or topology has been independently verified in the
  repository.
- JCS remains intentionally undefined until Phase 1 specification.
- No software version is supported by this foundation-only release.
- The repository has one maintainer; administrator protection enforcement is
  disabled to avoid lockout and remains documented residual risk.
- No software license is approved. Public visibility does not grant reuse
  permission.
- Data classification, application threat models, artifact-specific security
  scanners, and operational inventories wait for concrete implementation
  scope.

## Compatibility, deployment, and recovery

This is the initial documentation release. It introduces no runtime
compatibility, migration, or deployment obligation. The release artifact is
the reviewed Git commit, annotated tag, and GitHub release record.

If the release record is incomplete or misleading, do not rewrite the tag.
Publish a reviewed corrective version or mark the GitHub release withdrawn
with a durable explanation.

## What comes next

Phase 1 may define JCS only after the foundation release is verified. It must
preserve the approved phase order, distinguish facts from assumptions, and
make new implementation decisions through the documented architecture and
review process.
