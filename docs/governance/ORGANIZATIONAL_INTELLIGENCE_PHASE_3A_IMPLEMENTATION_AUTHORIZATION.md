## Proposed decision basis

Authorization would be supportable only if independent review confirms:

- ADR 0012 already accepts the read-only executive-interface boundary;
- Phase 3A is a synthetic cross-phase product foundation and does not activate
  canonical Roadmap Phase 3 - Knowledge Graph;
- the Executive Product Shell owns presentation and navigation only;
- the product is a fixed loopback local preview with no deployment path;
- all input is immutable, compiled, fabricated synthetic briefing data;
- there is no free-form prompt, file, source, registry, memory, model, retrieval,
  service, persistence, action, or external network path;
- the Python standard library is sufficient and no dependency or lock change is
  needed;
- view models, states, routes, tests, exact files, rollback, and stop conditions
  are bounded; and
- security, privacy, accessibility, and failure requirements are independently
  reviewable.

## Implementation gates

Before coding:

1. The complete architecture package exists at one remote exact head.
2. Documentation, links, whitespace, sensitive-value, scope, authority,
   canonical-consistency, and exact-manifest checks pass.
3. A distinct Work Mode reviewer returns **APPROVED** with no unresolved
   Blocking, High, or Medium finding.
4. The Chief Architect adopts this disposition for that exact Proposed head and
   authorizes only the bounded status-and-decision-evidence activation edit.
5. The same Work Mode reviewer freshly approves the resulting exact activation
   head.
6. The Chief Architect separately approves that unchanged activation head for
   architecture merge.
7. The reviewed package merges to canonical `main`.
8. The implementation owner fetches, synchronizes clean `main`, records the
   exact implementation base, and verifies the accepted documents.
9. The existing full Python test suite, documentation validation, and frozen
   lock check pass.
10. The implementation owner confirms the work has no real-information input and
   does not require a prohibited capability.

A changed architecture-package head reopens independent review and exact-head
Chief Architect authority. The status activation uses the same independent
reviewer; it does not transfer approval or assign a second reviewer.

1. Remain within the exact 31-file manifest.

if:

- any real or external information is required;

  registry, memory, service, external network, persistence, identity,

- a dependency, lock file, workflow, container, service, infrastructure,

- the local preview would bind beyond literal loopback;
- a test or demonstration requires private data, topology, credentials, or
