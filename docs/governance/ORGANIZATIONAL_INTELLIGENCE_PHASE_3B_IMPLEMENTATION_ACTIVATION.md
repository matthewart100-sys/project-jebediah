## Historical prepared full-package option

The earlier plan contemplated one local, single-operator, PDF-only intake and
review slice using:

- signed single-use authorization receipts;
- browser-pushed bytes on literal loopback;
- encrypted local object custody and SQLite metadata;
- rootless offline scanner, native PDF, and OCR workers;
- explicit review, retention, deletion, hold, backup, restore, and reset; and
- no downstream promotion, memory, model, retrieval, grounded-assistance,
  workspace, or deployment capability.

## Historical alternatives rejected

- Path-based CLI acquisition reverses the accepted pushed-envelope boundary.
- A multi-user or network service adds deployment and identity decisions.
- Host parsing lacks sufficient isolation.
- Cloud scanning/OCR exports data.
- DOCX expands dependency and attack surface without the first demonstration
  requiring it.
- Concurrent downstream promotion or retrieval would have bypassed the approved
  phase gate and obscured whether Phase 3B deletion and authority worked
  independently.

## Historical operational consequence

The contemplated historical implementation would have added durable encrypted
local state, interactive key custody, SQLite migrations, rootless OCI workers,
dependency/image maintenance, manual backups, and explicit cleanup. It would
have remained a repository candidate with no availability or deployment claim,
and all testing would have used generated synthetic PDFs.
